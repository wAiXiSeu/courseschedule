## 1. 产品概述与目标

### 1.1 产品定位

一款面向家庭场景的「儿童学习日程与管理工具」，以课程表为核心，串联学习计划 → 复习提醒 → 每日打卡 → 错题沉淀的完整学习闭环，帮助家长轻松安排、帮助孩子自主跟进。

### 1.2 目标用户

| 角色 | 画像 | 核心诉求 |
| --- | --- | --- |
| 家长（主要操作者） | 6-12 岁孩子的父母，负责排课、督促学习 | 高效排课、清晰掌握孩子学习进度、减轻督促负担 |
| 小朋友（主要使用者） | 小学生，每天查看今天要上什么课、做什么任务 | 界面简单直观，知道自己今天该做什么，打卡有成就感 |

> 默认按「家长操作 + 孩子查看」单一家庭视角设计；是否支持多孩子、是否区分家长/孩子账号见「待确认问题」。

### 1.3 产品目标（3 个正交目标）

1. **G1 排课高效**：家长 3 分钟内完成一周课程表安排，重复课程一次设置长期生效。
2. **G2 学习闭环**：从「学新内容 → 到期复习提醒 → 打卡确认 → 错题归档」形成完整可追踪链路，减少遗忘。
3. **G3 孩子可用**：孩子打开首页即见「今天的课程 + 今天的任务」，操作路径不超过 2 步，打卡有即时反馈。

### 1.4 核心价值

- 对家长：从「口头督促 + 脑子记」升级为「一张表 + 自动提醒」，降低管理成本。
- 对孩子：可视化的日程与打卡成就，培养自主学习习惯。

## 3. 需求池（Requirements Pool）

优先级定义：**P0 = Must have**（首发必须有）、**P1 = Should have**（应有，可次版本）、**P2 = Nice to have**（锦上添花）。

### P0 必须有

| 编号 | 需求 | 简要验收标准 |
| --- | --- | --- |
| P0-1 | 课程表管理（增删改查） | 支持按周视图展示；单条课程含名称、地点（校内/校外）、星期、开始/结束时间、颜色标签；删除需二次确认 |
| P0-2 | 课程周期重复 | 支持按周重复（每周同一天同一时段），设置后自动填充后续周视图 |
| P0-3 | 今日视图（孩子首页） | 打开首页即显示今天日期、今日课程时间轴、今日待办任务（学习任务 + 到期复习任务），无需点击进入 |
| P0-4 | 学习计划 | 计划含标题、目标描述、起止日期、关联科目；计划可拆解为每日/每周任务，任务出现在今日视图 |
| P0-5 | 复习计划（遗忘曲线） | 录入"学习内容"后自动生成复习节点（默认间隔 1/2/4/7/15 天，可自定义）；到期复习任务自动出现在当日任务列表；完成后进入下一间隔 |
| P0-6 | 每日打卡 | 任务可勾选完成；打卡后立即有视觉反馈（如星星 +1）；支持当日补卡（仅限当天） |
| P0-7 | 打卡统计 | 显示今日完成率、连续打卡天数、本周打卡日历（7 天格子） |
| P0-8 | 错题本录入 | 录入字段：科目、题目内容（文字 + 图片）、错误原因（概念不清/粗心/不会做等标签）、录入日期 |
| P0-9 | 错题本浏览 | 支持按科目、按知识点/标签、按时间筛选浏览错题列表 |

### P1 应该有

| 编号 | 需求 | 简要验收标准 |
| --- | --- | --- |
| P1-1 | 多孩子支持 | 可创建多个孩子档案，各孩子独立课程表/计划/打卡/错题，顶部可切换 |
| P1-2 | 复习间隔自定义 | 家长可调整遗忘曲线间隔序列并按科目保存为模板 |
| P1-3 | 任务提醒 | 到点提醒当日任务/复习（Web 端浏览器通知；App 端推送，视平台而定） |
| P1-4 | 错题掌握度标记 | 错题可标记"已掌握/待巩固"，已掌握错题可进入"再复习"队列 |
| P1-5 | 成就激励 | 打卡里程碑成就（连续 7/21/100 天），孩子端展示徽章 |
| P1-6 | 月视图课程表 | 课程表支持月视图缩放查看 |

### P2 可以有

| 编号 | 需求 | 简要验收标准 |
| --- | --- | --- |
| P2-1 | 错题导出打印 | 导出为可打印练习卷（PDF），支持筛选后导出 |
| P2-2 | 学习周报 | 每周生成学习总结（打卡率、复习完成率、新增错题数），家长端查看 |
| P2-3 | 数据云同步与多设备 | 账号体系 + 数据云端同步（依赖平台决策，见待确认问题） |
| P2-4 | 错题拍照 OCR | 拍照自动识别题目文字，减少手工录入 |
| P2-5 | 家长/孩子双账号权限 | 孩子账号仅可查看与打卡，家长账号可编辑全部内容 |

## 5. 待确认问题（Open Questions）

| # | 问题 | 影响范围 | 倾向建议 |
| --- | --- | --- | --- |
| Q1 | 目标平台是 Web（PC/手机浏览器）、微信小程序，还是原生 App？ | 整体技术选型、提醒能力（浏览器通知 vs 推送） | 建议 Web（响应式）或小程序起步，开发成本低 |
| Q2 | 是否需要支持多个孩子（多档案）？ | 数据模型、顶部孩子切换器（P1-1） | 建议 P1 支持多孩子，首发单孩子 |
| Q3 | 是否需要账号体系与云端同步（换设备不丢数据），还是本地存储即可？ | 是否做登录、后端与 P2-3 | 首发本地存储 + 后续云同步更稳妥 |
| Q4 | 家长和孩子是否分账号、分权限（孩子只能看/打卡，家长能编辑）？ | 权限模型（P2-5）与登录设计 | 首发可共用设备不分账号，视 Q3 决策 |
| Q5 | 复习提醒的触达方式：仅应用内展示，还是需要推送/提醒（什么时间点提醒）？ | P1-3 提醒功能 | 至少应用内「到期任务」高亮，推送次版本 |
| Q6 | 错题录入是否需要支持拍照/图片？是否需要 OCR 识别（P2-4）？ | 错题本字段与存储（图片体积） | 首发支持贴图、不支持 OCR |
| Q7 | 是否需要校内课表整体导入（如从模板/Excel 一键导入），还是逐条录入？ | 课程表录入效率 | 首发逐条 + 周期重复；导入列 P2 |
| Q8 | 目标孩子年龄段？影响界面风格（低龄大图标 vs 大龄简洁风）与激励体系 | 视觉设计、文案语气 | 按 6-12 岁小学生设计 |
| Q9 | 数据是否需要导出/备份（错题打印、学习周报）的优先级如何？ | P2-1 / P2-2 排期 | 视客户反馈决定 |

## 6. 名词解释

| 名词 | 定义 |
| --- | --- |
| 遗忘曲线复习 | 按艾宾浩斯遗忘曲线设定复习间隔（默认 1/2/4/7/15 天），到期自动生成复习任务 |
| 打卡 | 孩子完成当日任务后的确认动作，累计形成连续打卡天数 |
| 错题掌握度 | 错题的状态标签：待巩固 / 已掌握，用于筛选和再复习 |
